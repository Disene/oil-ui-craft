# Craft 增强：交互状态、表单、弹层与键盘行为

> 本文是 Disene Fork 独立编写的设计与实现参考，不是官方 Pro 代码。只在**复杂输入、弹窗/抽屉、数据加载、批量操作或实际交互变更**时读取。项目原有组件、路由、鉴权与数据合同优先。

## 设计一个交互前，写清 4 件事

**触发源、正在做的事、可观察结果、返回路径。** 例如：「列表项 → 查看详情 → 显示对象状态与两项权限 → 返回后保留原筛选和该行焦点」。页面装饰不能替代这四项。

| 场景 | 需要设计的实际状态 | 常见失败 |
| --- | --- | --- |
| 搜索/筛选 | 空输入、有结果、无结果、请求中、失败、旧数据待更新 | 失败显示“无记录”；刷新把查询清空 |
| 表单 | 原值、正在输入、验证错误、提交中、成功、失败、已提交但回执丢失 | 报成功前未核实；重试把请求重复发送 |
| 下拉/组合框 | 未展开、展开、键盘高亮、无匹配、加载中、输入法组字 | 点击外关闭不还焦点；中文组字 Enter 被误认作选项确认 |
| 弹窗/抽屉 | 打开、聚焦、长内容滚动、取消、确认、异常关闭 | Tab 逃出；Escape 后焦点丢失；背景仍可操作 |
| 批量选择 | 无勾选、部分勾选、跨筛选、选中版本过期、执行中、部分失败 | 查看态和勾选态混淆；选择后找不到操作入口 |
| 异步详情 | 旧请求仍在途、新对象已打开、错误、恢复 | 旧请求覆盖新对象；页面“已完成”但数据尚未更新 |

只挑这次功能真的触及的状态，不把表中所有状态强制套给所有页面。

## 控件结构要遵循语义

- **输入框**：可见标签与可访问名称必须存在；placeholder 不能单独代替标签。文本输入、搜索、必填与错误通过标准关联（label / aria-describedby / aria-invalid）表达。
- **状态选择**：按钮触发的下拉列表要有展开状态、可预测的选择行为和键盘入口。若用原生 select 能满足体验，优先复用它，不为造型新写一个难以维护的控件。
- **中文输入法**：组合框响应 Enter、Escape、方向键前检查 composition 状态。组字 Enter 只确认输入法，不能自动提交/选择。检测键盘事件中的 isComposing 和 keyCode 229 是常见防线，但仍需真实输入法验证，不能用合成事件证明跨平台。
- **对话框**：优先使用原生 `<dialog>` 的 modal 行为，或复用项目里经过测试的 Dialog。打开时焦点到相关控件或描述；Tab 留在模态范围内；Escape/取消不会写数据；关闭后焦点返回有效的打开入口。关闭后入口已消失时，选择最近合理的上下文元素。
- **抽屉**：若是模态抽屉，采用同样的焦点约束与背景隔离；若是非模态的持久详情面板，则不要错误地锁住键盘，应该让列表与详情都可达。
- **批量操作**：勾选是暂存目标，不是提交。已选数量在勾选附近可见；主要动作使用唯一的既有事务/确认流程；取消保留或清除勾选的规则清晰，且焦点返回实际触发元素。
- **视觉焦点**：标题被程序聚焦可以显示清晰外框，但不能因为 `:focus` 全局样式让非链接标题出现误导性下划线。不要仅凭蓝色推断“可点击”。
- **禁用与失败**：只禁用当前真正不可执行的动作；列表加载失败不能自动把全站所有按钮禁用。保留用户输入并提供明确的恢复入口。旧数据必须表明时效性。
- **减少动态效果**：支持 reduced-motion。反馈动效短、可察觉、不依赖动画传达唯一信息。

## 真实操作路径的轻量验证

优先使用既有项目的浏览器测试；没有时才考虑 Fork 附带的可选 `scripts/ux_journey.py`。从**真实入口**开始，不只测子组件：打开列表 → 定位对象 → 修改或取消 → 返回 → 焦点与原筛选恢复。

用观察结果等待异步状态，不用纯延时碰运气。分别记录：

1. 程序/断言实际执行是否成功；
2. 浏览器有无未捕获异常、溢出或关键状态异常；
3. 视觉截图有没有真实检查；
4. 业务正确性是否由合适测试或人员验证。

单个 PASS 不能替代后面三种证据。报告来源、视口、测试数据类别与没覆盖的状态。公开 Fork 内不得写客户数据、实际账号、Cookie 或生产密钥。

## 组件精修时的质量判断

对控件截图同时检查默认、焦点、展开、禁用、忙碌、错误及窄窗状态里**此次实际发生的几种**。动作区域与文字对齐，文字缩放后不裁切，弹层贴边时能翻转定位；关闭、返回及重试必须留下可预测状态。不同页面复用同一语义和设计 Token，但别把所有控件强制做成一套相同的外观。
