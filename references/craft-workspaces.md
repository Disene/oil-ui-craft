# Craft 增强：既有产品、后台工作区与响应式布局

> 本文属于 Disene Fork 的独立扩展，不是官方 Oil UI Pro 的私有内容。只在**已有产品改版、数据后台、列表详情或复杂工作台布局**时读取。新营销页或纯视觉探索仍沿用上游规则。

## 先选择修改类型，而不是一律重构

| 用户真正要什么 | 允许改什么 | 不应顺手做什么 | 验收重点 |
| --- | --- | --- | --- |
| **视觉精修**：现有任务已正确，但不清楚、不统一、不好看 | 字体、层级、间距、可视化、信息分组、共用 token/组件 | 权限、数据源、交互合同、保存时机 | 同一任务前后截图 + 局部交互 |
| **流程改进**：用户必须绕路、滚动、反复操作 | 入口位置、任务步骤、焦点/返回、反馈、操作顺序 | 没有必要的风格重选、底层服务重写 | 从真实入口走通的操作路径，含取消/失败 |
| **新增功能**：有新行为或状态 | 复用现有组件与设计语言，增加必要状态和局部布局 | 另建平行设计系统、把所有界面重做 | 新行为状态和相邻回归 |

如果用户明确要求整站视觉重构，可以重新讨论结构和视觉方向；已有 DESIGN.md 中的业务安全约束始终有效，但旧设计默认值不应永久冻结为必须保留的布局。已选定视觉方向时不要再做三套平行首屏。

## 后台选布局：看任务、不是套模板

- **表格 / 矩阵**：用户需要横向比较多个账号、订单、指标时首选。在桌面上对齐字段，不用同一种单卡布局反复堆行。列宽优先留给可变长主体（账号名、问题、时间），固定短值（状态、权限）窄列，长值能换行。
- **列表 + 详情**：用户需要先筛选、随后核对或修改一条记录。宽屏可并排；窄屏在同工作区列表/详情切换，返回时保留查询、筛选、滚动和触发项焦点。不要把整张列表压成 390px 宽窄列。
- **密集工作台**：用户需同时处理数据、状态和多步操作时，先建立主工作区与辅助区；全局导航保持稳定，局部工具栏按「返回/当前位置 → 次操作 → 主操作」分级。没有任务需要就不增加第四层卡片标题或一长串解释。
- **分析图表**：选择图种由比较任务决定；零值、两组都很小、负值、长标签、深浅背景是内容适配测试，不是统一给所有图附一个大号图例。标签不应只靠颜色区分，避免两个小值重叠。

## 信息层级和状态不能被压缩掉

1. **当前在哪里**：全局导航 / 页面标题 / 当前记录彼此有层级，返回去往何处可以预测。
2. **此处做什么**：页面级主要操作通常只有一个；低频批量导入、日志可弱化而不隐藏。
3. **对象是什么**：名称 > 角色/类型 > 启停/最新状态 > 各项权限/数据事实；排列位置应服务用户实际比较顺序。
4. **缺省和未知不同**：未授予、未加载、无记录、权限不足和系统失败分别表达，不用空白或灰色标签推断。
5. **查看和选择不同**：当前行 / 焦点 / 悬停 / 批量勾选有独立可见表现。不同状态可叠加，不能以同一整行蓝底同时表示多个状态。
6. **选择后可操作**：列表中途勾选后，应在当前视野中有「已选 X 个」和去往原有操作区的入口；保留单一实际提交/确认逻辑。不要同时建立顶部/底部两个有副作用的操作系统。
7. **长名称与狭窄空间**：遇到长单词、中文标题、两字按钮、放大字体不能被迫逐字竖排或被裁切；优先分列/折行，不把字号无限缩小。

## 响应式不是仅检查无横向滚动

针对受影响主流程，根据真实项目设备选择桌面、中间宽度、390px 或更窄窗口（不要求每次跑固定的全矩阵）。分别确认：

- 页面级主动作的位置、标题与返回是否仍可读；没有多层页头占去整屏。
- 桌面比较关系是否保留；窄屏改为单栏或「列表 / 详情切换」时，内容完整、焦点和历史状态可恢复。
- 长账号名、空行、多项权限、批量已选状态、错误重试在真实宽度下都有可用入口。
- 125% / 200% **CSS 缩放、浏览器原生缩放、触屏真机是不同证据**；做过其中一项不能报告另外两项通过。
- 水平溢出检查只证明布局可容纳，不证明触摸目标够大、文字可读或主要功能可达。

## 一轮可用交付

选代表性任务 → 对受影响页面与状态拍基线 → 只修改相应组件与样式 → 实际进入并操作 → 看修改前后相同状态截图 → 保留可读性和业务结果 → 仅记录未解决问题。

视觉没有显著进步时，先评估布局主张是否错误，别在旧结构上无限叠加 CSS 覆盖。设计候选、代码测试、真人验收、合并和部署分别报告；有产品主线时写回其既有记录。
